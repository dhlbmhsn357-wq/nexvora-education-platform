# LifePilot AI - Domain Model - Value Objects

**Status:** Milestone 0.3 draft for approval.

## Value Object Rules

| Rule | Requirement |
|---|---|
| Immutability | Value Objects are created valid and replaced, not mutated in place. |
| Validation | Validation is deterministic and belongs in domain or application validation depending on whether it is a business invariant or input-shape rule. |
| Equality | Equality is based on all significant values, not database identity. |
| Serialization | Stored and transmitted using stable primitive representations; localized display text is never the serialized value. |
| Cross-context usage | Only stable identifiers and approved simple values may cross contexts. Complex business Value Objects remain owned by their context. |

## Serialization Standards

- IDs serialize as stable strings.
- Dates/times stored as UTC instants except user-visible date-only concepts such as PlanDate.
- Locale-sensitive labels are rendered at the presentation boundary, not stored as domain values.
- Sensitive values must be excluded or minimized in integration events and logs.
- Provider-specific fields stay behind anti-corruption layers.
