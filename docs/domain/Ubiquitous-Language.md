# LifePilot AI — Ubiquitous Language Dictionary

**Status:** Proposed vocabulary; approval is required before it becomes binding for Milestone 0.2.  
**Rule:** A term marked **TBD** is intentionally not defined as a Version 1 behavior. It must not be implemented, inferred, or used as a synonym for a defined term until Product Owner approval.

## 1. Dictionary rules

- **Owner** is the sole domain permitted to change the authoritative state of the term.
- **Refs** lists domains allowed to hold an identifier, immutable fact, or read projection. Referencing never grants write authority.
- **Form** uses: `Aggregate`, `Entity`, `Value Object`, `Projection`, `Domain Event`, `Command`, or `Technical Record`.
- **Mutability** describes the term's authoritative state: `Mutable`, `Immutable`, or `Derived/replaceable`.
- A term with no approved lifecycle is marked **TBD**, not assigned a fictional workflow.
- Events are immutable facts; commands are requests and are not facts; projections are replaceable views and not sources of truth.
- `UserId`, UTC instant, locale, and approved domain identifiers are controlled shared references, not shared writable entities.

## 10. Required distinctions

| Easily confused terms | Binding distinction |
|---|---|
| User vs Profile | User is the account/ownership identity; Profile is mutable personalization data. |
| Goal vs Plan vs Daily Plan | Goal is desired outcome; Plan is domain-owned intended content; Daily Plan is the cross-domain day-level organization. |
| Task vs Plan Item vs Activity | Task is TBD; Plan Item is a mutable planned item; Activity is an immutable recorded fact. |
| Progress vs Progress Percentage vs Completion | Progress is derived interpretation; Percentage is one metric representation; Completion is a source-domain fact. |
| Achievement vs Completion | Completion is a state/fact; Achievement is an optional recognition triggered by approved conditions. |
| Workout vs Workout Program vs Workout Session | Workout is a TBD fitness activity/template concept; Program is a plan; Session is recorded execution. |
| Meal vs Recipe vs Meal Plan | Meal is a record or planned occurrence; Recipe is reusable composition (TBD); Meal Plan is a nutrition plan. |
| Prayer vs Prayer Session | Prayer is the spiritual practice/progress reference; Prayer Session is TBD and must not duplicate it. |
| AI Recommendation vs AI Suggestion vs AI Plan | Recommendation/Suggestion are advisory output; AI Plan is a proposal that becomes a real plan only after target-domain validation. |
| Notification vs Reminder | Notification is any durable user message; Reminder is a time-oriented notification governed by approved scheduling policy. |
| Dashboard vs Insight vs Statistics | Dashboard composes projections; Statistics are derived numbers; Insight explains those numbers. |
| Event vs Command vs Job vs Log vs Audit | Event is a business fact; Command is a request; Job executes background work; Log is telemetry; Audit is accountable evidence. |
| Role vs Permission vs Feature vs Premium | Role classifies user authority; Permission authorizes action; Feature is capability; Premium is commercial entitlement. |

## 11. Terms intentionally excluded from binding use

The following terms are present because they were requested, but cannot be made binding without a separate approved functional decision: **Mission, Task, Habit, Study Plan, Lesson, Chapter, Recipe, Ingredient, Calories, Protein, Carbohydrates, Fat, BMI, Prayer Session, Quran Session, Subscription**, and portions of **Workout**, **Reminder**, and **Streak**.

Until approved, feature specifications must use the nearest defined term only when it is semantically correct; otherwise they must introduce a proposed term and seek Product Owner approval.
